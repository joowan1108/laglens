How to read LagLens

A robot policy plans 16 moves at a time (a chunk) and needs time d (latency, in steps of 100 ms) to compute each plan; the robot executes the first h moves (horizon 4, 8 or 11; 11 is the longest that fits a 16-move plan at every latency) and then switches to the next plan. Sync waits while it thinks; naive async keeps moving and switches plans abruptly; inpaint async keeps moving and makes the new plan continue the old one (the start of the new plan is filled in from the old one). Every schedule (strategy × latency d × horizon h) was run from the same 30 start states, on two tasks: PushT (push a T-block onto a goal) and Catch the ball (touch a rolling ball within 8 s).

  1. A Pair Overview, start here: each cell compares two schedules (row = baseline, column = candidate). Purple = the candidate succeeds more often on the same start states, grey = less. Compared are schedules at the same latency (a choice you can make), the same strategy and h at two latencies (what more latency costs), and any schedule against d = 0 at the same h (at d = 0 all strategies are the same). The rest is hatched: it mixes two causes. On PushT, h alone matters a lot (sync at d = 0: 27 % at h = 4, 70 % at h = 8, 73 % at h = 11), which is why h is only compared with the same h across latencies. Framed = still unlikely to be chance after correcting for all compared pairs (102 per task; false discovery rate 5 %). Click a cell to compare that pair. Right of the matrix, the ranking lists the schedules at one latency (the pair's, or the one chosen in d = 2 / 4) by their absolute value in all three runs: click a row to make it the candidate.
  2. B: every schedule against the chosen baseline (0 = baseline), by latency d and horizon h. Small hollow marks = the same schedule simply run again: the spread that chance alone produces.
  3. C: the 30 start states of that pair, the ones that flip first. Narrow cells = the same schedule run again; ≈ = the outcome is not the same in every run. Right: what each schedule paid there (idle time, outdated plan, or jumps). Click a row to replay it.
  4. D: the replay, baseline and candidate on one board, opened at the moment that most likely explains the pair: the plan being executed, where things were when it was planned, and jumps when the plan switches.
  5. E: when the policy was thinking, when the robot acted or stood idle, how big each jump was next to an ordinary step (grey), and how each run ended.

Keyboard: ←/→ step, space play/pause, Esc clears the time window and the seed selection.
