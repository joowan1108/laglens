How to read LagLens

A robot policy plans 16 moves at a time and needs time d to compute each plan. Sync waits while it thinks; naive async keeps moving and switches plans abruptly; inpaint async keeps moving and makes the new plan continue the old one. Every schedule (strategy × latency d × horizon h) was run from the same 30 start states, on two tasks: PushT (push a T-block onto a goal) and Catch the ball (touch a rolling ball within 8 s).

  1. A Pair Overview, start here: each cell compares two schedules (row = baseline, column = candidate). Purple = the candidate succeeds more often on the same start states, grey = less; framed = unlikely to be chance. Click a cell to compare that pair.
  2. B: every schedule against the chosen baseline (0 = baseline), by latency d and horizon h: how each strategy loses as the policy gets slower.
  3. C: the 30 start states of that pair, the ones that flip first. Click one to replay it.
  4. D: the replay, baseline and candidate on one board: the plan being executed, where things were when it was planned, and jumps when the plan switches.
  5. E: when the policy was thinking, when the robot acted or stood idle, and how big each jump was.

Keyboard: ←/→ step, space play/pause, Esc clears the time window and the seed selection.
